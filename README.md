# IMPRINT

A spec portfolio site for a fictional brand and advertising studio. Next.js 15 App Router,
React 19, TypeScript. Every image on the site is generated by a script in this repo — there is
no stock photography and no binary art committed by hand.

```bash
npm install
npm run dev
```

Deploying is `next build` and nothing else — see [DEPLOY.md](DEPLOY.md). All generated
imagery is committed under `public/`, because none of the generators run on Vercel.

---

## Hero footage

**No stock-footage tier was used. All 180 hero frames are generated procedurally**, by
`scripts/generate_frames.py`. The original brief specified a three-tier ladder — scrape Pexels,
then Coverr / Wikimedia / archive.org, then fall back to generation. That ladder was removed
before the build rather than attempted, for three reasons:

1. Pexels renders search results client-side, so fetching the search HTML yields no
   `videos.pexels.com` URLs, and the brief correctly forbids constructing them from IDs.
2. Generated frames are locked to the site's own palette and licence-clean, which stock is not.
3. It contradicted the project's own principle — the brand boards are generated for exactly
   the same reason ("generate it, don't photograph it").

A consequence worth noting: **ffmpeg is not a dependency.** The generator writes
`frame_0001.webp …` directly, so there is no video to extract from and no assembly step.

The frame pipeline is source-agnostic, so swapping in real macro footage later needs no
component changes — extract to `public/frames/frame_%04d.webp` and re-run the count into
`app/data/frames.ts`.

### How the ink is made

Two fields do two different jobs, because using reaction-diffusion for both does not work:

- **Mass** — an eight-octave fBm field thresholded at a level set. Ink spreading through paper
  is a wetting front through a heterogeneous absorbency field, and a level set on fractal noise
  models that well: the coastline is irregular at *every* scale, with bays, peninsulas and
  detached islands speckling off the edge. Nothing here is a radial gradient.
- **Edge** — Gray-Scott reaction-diffusion, whose V field displaces the threshold so the
  boundary carries fibrous filigree, stepped 3 iterations per frame to keep it alive.

Two parameters carry most of the look, and both were set by measurement rather than taste:

- **Base wavelength (26 cells).** This sets feature scale. At the 10 cells this started on, the
  largest blot was over 50% of frame width and the result read as camouflage; at 26 it is
  ~18%, with distinct blots and islands across the frame and specks down to 2px.
- **Composition (density + suppression).** Feature scale alone is not enough: a level set on
  plain fBm distributes blots *evenly*, which reads as leopard print however good the per-blot
  numbers are. A long-wavelength density field biases the threshold into dense and open
  passages, and the sparsest lobes have the threshold pushed beyond the range of the mass
  field so they hold no ink at all — merely lowering density leaves scattered specks that
  spoil an open area. Measured: coverage across a 4x4 grid runs 0% in the emptiest cell to
  ~51% in the densest, against a near-flat field before.
- **The 8th octave.** Fine threshold noise severs the thin bridges between blots, which is what
  holds percolation off. At 7 octaves the ink connects into a single mass by 24% coverage
  (largest blot 44% of width); at 8 it is still 17% at 28% coverage. Coverage is capped at 30%
  for the same reason — a 2D level set percolates near 50% area whatever the wavelength.

Gray-Scott was tried as the mask itself first and does not read as ink at any parameters. In
the coral/worm regime it produces a Turing labyrinth that looks like a fingerprint; seeded with
regions large enough to read as blots, the reaction only sustains at boundaries and hollows the
interiors into rings. It is also expensive — the labyrinth is maximum-entropy detail, and that
version of the sequence weighed **14.7 MB against 4.6 MB** for solid masses.

Growth is a falling threshold placed at the quantile matching a target coverage, so the bloom
from 18% to 30% ink is exact rather than emergent. Two plates composite the same mask — ink
`#17150F` at full strength and cyan `#0090C1` at 28% offset by (7, 4)px — and that
misregistration is what makes it look printed. It measures 4–5% of frame pixels and is 92%
one-sided (ink up-left of the fringe), which is the point: at the 22%/5px it started on the
geometry was already correct but too faint to see.

There is no baked vignette. The CSS scrim in the hero handles legibility, and a darkening ramp
in the frame itself drags most of the image away from true paper.

## Design tokens

| Token | Value | Use |
|---|---|---|
| Paper | `#F2EEE6` | page background |
| Deckle | `#E4DED1` | alternate surface bands |
| Ink | `#17150F` | display type, cursor |
| Graphite | `#55504A` | body copy |
| Cyan | `#0090C1` | the single accent |
| Cyan-hi | `#00A6DE` | CTA hover only |
| Rule | `rgba(23,21,15,0.14)` | hairlines |

Cyan appears on eyebrow labels, the cursor hover ring, CTAs, link underlines and focus rings —
nowhere else. There is no second accent and no terracotta anywhere in the site's own chrome.
Client palettes appear only inside generated project imagery and the project-page swatches.

**Type** — Instrument Serif 400 (display), Archivo 300/400/500 (body), JetBrains Mono 400
(utility). Three faces total. The six client typefaces are rendered into board images at build
time and are never loaded as web fonts.

**Signature element** — the printer's registration mark: a crosshair whose lines extend past
the circle on all four sides. It is the cursor, the section divider (replacing horizontal
rules) and the process-step marker.

No `border-radius`, no drop shadows, no gradients beyond the two hero scrims and the CTA glow.
No footer and no cookie banner. Navigation is a fixed top bar plus a full-screen overlay,
alongside the work tiles, the back link and the next-project link.

## Notable implementation decisions

These differ from the original brief, each for a reason found during the build:

- **The cursor is a blurred paper-white disc, difference-blended** — ~26px at rest, ~70px on
  `[data-cursor]`, blur 5px to 9px, lerp 0.14, no text label. Difference blending is safe
  here precisely because the disc is `#F2EEE6`: it computes to near-black on paper and
  near-white on ink. It is not safe with cyan — `#0090C1` differenced against paper gives
  `#F25E25`, the terracotta this design excludes — which is why the cursor carries neither
  cyan nor labels.
- **Reduced motion is handled in JS as well as CSS.** Canvas scrubbing is not a CSS animation,
  so the standard reset cannot reach it; the hero collapses to a static 100vh section carrying
  both the identity block *and* the closing CTA, since beats 2–4 are scroll-driven and those
  users would otherwise never see a call to action.
- **`animation-iteration-count: 1` is in the reduced-motion reset.** Without it,
  `animation-duration: .01ms` loops the marquee ~100k times a second instead of stopping it.
- **`cursor: auto` is restored under reduced motion, not just on touch**, or those users get no
  visible cursor at all.
- **One scroll-progress source.** The rAF loop writes a `useMotionValue` and every beat reads
  it, so the copy can never disagree with the frame on screen. There is no `useScroll` on the
  hero and no scroll event listener.
- **Frames preload in two passes** — every 8th first, then backfill — and the draw falls back
  to the nearest loaded neighbour, so the scrub is usable long before all 180 have arrived.
- **`devicePixelRatio` is capped at 1.5.** The source frames are 1280px wide; a 2× backing
  store on a 1440p display upscales into ~5120px for no visible gain.
- **The ink runs behind the whole document, not just the hero.** The canvas was inside the
  hero's 500vh container, and where that container ended the darkest row of the hero scrim met
  the lightest cream of the page — a hard seam. Lifting it to a fixed layer under everything
  removes the boundary rather than disguising it, and a paper veil (0 -> 0.88 across the hero's
  last 40vh) lets the ink recede instead of being cut. Measured over the moving ink: body copy
  6.50-16.05:1, headings 15.91-16.06:1, at three scroll positions per section.
- **The cursor trail carries IMPRINT's own six client monograms**, generated by
  `scripts/generate-monograms.mjs`. Real-world logos are deliberately not used: a studio site
  scattering trademarked marks reads as a claim to have worked for those companies, and would
  undercut the six spec case studies a scroll away.
- **Hero frame composition is a generator concern.** See above — the fix was a density field
  in `generate_frames.py`, not anything in a component.
- **Mono labels over the canvas are paper, not cyan.** Cyan at 0.68rem over a mid-tone canvas
  is low contrast whatever the scrim does; the accent moved to an 11px registration mark beside
  each label, where a solid shape carries the colour without needing to be read as text.
- **Beats 1 and 2 have their own local backdrop**, the same device beat 4 already used. Once
  the ink was resolved to its proper feature scale the large dark masses that used to sit
  behind that copy were gone, and the body text measured 2.76:1 mean / 1.68:1 worst against
  the finer speckle — under the 4.5:1 body floor. With the backdrop it is 5.54:1 mean.
- **Registration marks use a positive inset.** A negative one puts them outside the content
  column, and on mobile that column is the full viewport, so they widened the page past the
  screen.
- The studio is dated **EST. 2019** — the brief's "EST. 2026" contradicted its own 2025 project
  dates.

## Scripts

```bash
npm run dev              # localhost:3000
npm run build            # static export of / and all six /work/<slug>
npm run start            # serve the production build
npm run generate:frames  # regenerate the hero sequence + app/data/frames.ts (~60s)
npm run generate:boards  # regenerate the 24 brand boards with Puppeteer (~40s)
```

Regenerating frames requires Python 3 with `numpy` and `Pillow`. Regenerating boards requires
network access for Google Fonts; the script asserts each typeface actually loaded rather than
silently screenshotting a fallback face.

## Verification

```bash
node scripts/verify.mjs http://localhost:3100   # 308 browser checks
python scripts/analyse_frames.py                # hero frame image metrics
node scripts/record.mjs http://localhost:3100   # screen recordings into captures/
```

`analyse_frames.py` measures the properties that decide whether the frames read as macro ink
on paper — feature scale (blot count, largest blot as a share of frame width, speck sizes),
size distribution, paper warmth against `#F2EEE6`, the cyan fringe's strength and
one-sidedness, and two composition measures: coverage spread across a 4x4 grid, and the
largest clean-paper rectangle. Those last two exist because the first set can all be on target
while the image still reads as an even texture. It is how the numbers above were set.

`record.mjs` writes `captures/imprint-scroll.webm` (47.4s: ~20s hero scrub, then every
section) and `captures/imprint-cursor.webm` (20s of hover states). It captures sequentially,
one page step per video frame, rather than using Puppeteer's screencast — screencast's capture
rate is not uniform under varying load, and no single retiming factor corrects it.


83 checks against a real browser — HTTP status codes, sampled canvas pixel data, computed
styles and live DOM counts. Nothing is asserted by reading source. It covers: all seven routes;
every board image returning 200 with a dominant colour that matches its own project's palette
(which proves both that the boards are not blank and that each brand rendered in its own
colours); the canvas being non-uniform on a fresh load with no scroll; the staggered identity
entrance; the full beat order holding to the end of the hero; the cursor turning cyan with a
VIEW label; the trail spawning on the home hero and *not* on `/work/vyntrix`; both being absent
under touch and reduced motion; the manifesto revealing word by word and being fully lit once
centred; the marquee; every navigation link including the next-project wrap; and the 375px
layout.

All 308 pass against the production build.

## Deploy

Fully static apart from Next's image optimiser. Any Node host works:

```bash
npm run build && npm run start
```

On Vercel, push the repo and accept the defaults — the framework preset, build command and
output directory are all detected. `public/` is 13.2 MB, almost all of it the hero frame
sequence, which is within the limits of any static host. If you deploy somewhere without Next's image optimiser, add
`images: { unoptimized: true }` to `next.config.ts`.

Set the real origin in `app/layout.tsx` (`metadataBase`) before shipping, so Open Graph image
URLs resolve absolutely.
